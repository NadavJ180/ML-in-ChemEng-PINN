# Pipeline Guide

This is a practical run-order guide: which script to run when, what it needs, what it
produces, roughly how expensive it is, and when you can skip it. It complements — and
does not replace — the README's own [Usage](README.md#-usage) section, which documents
each script's individual flags in more detail.

For automation, [`run_pipeline.py`](run_pipeline.py) runs every stage below in order by
invoking these same scripts as subprocesses:

```bash
python run_pipeline.py              # run everything, in order
python run_pipeline.py --list       # show the stage list without running anything
python run_pipeline.py --from phs   # resume from a specific stage onward
python run_pipeline.py --stages train,verify_model   # run only specific stages
```

## What a fresh clone actually has

Only `models/*.pth` (30 trained checkpoints) and the source tree are committed to git.
**`data/` and `plots/` are gitignored and empty on a fresh clone** — `data/cases_metadata.json`,
`data/tensors/`, `data/hallucinations/`, `data/phs_scores/`, and everything under `plots/`
are all regenerated by the scripts below, not shipped. This means:

- You get the 30 trained models for free — **you do not need to retrain to reproduce
  the hallucination / detection / figure results.**
- You do need to regenerate `data/cases_metadata.json` before running anything else
  (every downstream script looks a case up by `case_id` in that file).
- Everything from hallucination generation onward is a real computation, not a cached
  artifact — there is no shortcut to instant figures/tables on a fresh clone.

## Stages, in order

| # | Stage | Script | Needs | Produces | Cost | Skip when |
|---|-------|--------|-------|----------|------|-----------|
| 1 | Sample cases | `src/data/sampler.py` | nothing | `data/cases_metadata.json` | seconds | `data/cases_metadata.json` already exists — it's seeded (42) and fully deterministic, so rerunning just reproduces the same file byte-for-byte |
| 2 | Generate tensors | `src/data/generate_datasets.py` | stage 1 | `data/tensors/{case_id}.pt` | seconds–~1 min | **you only need this if you're going to retrain** (stage 3 hard-requires the `.pt` files); every later stage builds its own points on the fly and doesn't read `data/tensors/` |
| 3 | Train | `src/models/train_model.py` | stages 1–2 | `models/{case_id}_best.pth`, `plots/loss_history/` | **expensive** (Adam 5000 epochs + L-BFGS per case; the slow step) — but **automatically skips any case_id that already has a checkpoint** | all 30 `models/*.pth` already exist (true on a fresh clone) — running this stage will just print 30 "already exists" skips and do no real work |
| 4 | Verify model(s) | `src/models/verify_model.py` | stage 3 (a trained model) + stage 1 | `plots/{case_id}_verification_dashboard.png` | seconds per case (inference only, no training) | optional sanity check — not part of the detection pipeline itself, just confirms a checkpoint matches the analytical solution. Not previously documented in the README's Usage section. |
| 5 | Generate hallucinations | `src/hallucinations/generate_hallucinations.py` | stage 3 (models) | `data/hallucinations/{case_id}_hallucinations.pt`, `hallucination_index.csv`/`.json` | moderate (forward passes only, all 30 cases) | never — **fully regenerates every run**, no skip-if-exists. Required before stage 7. |
| 6 | Verify hallucinations | `src/hallucinations/verify_hallucinations.py` | stage 3 (models) | `plots/hallucination_verification/` | moderate (small 96×96 grids, but gradient-tracked residuals) | optional diagnostic audit — not a dependency of any later stage |
| 7 | Evaluate PHS | `src/detection/evaluate_phs.py` | stage 5 (hallucination index) + stage 3 (models) | `data/phs_scores/phs_components_raw.csv`/`.json`, `plots/phs_evaluation/*` | **the second-most expensive step** — full-resolution PDE-residual autograd across 30 cases × 31 fields each (5 perturbation types × 6 epsilons + 1 clean baseline). Use `--n_interior 3000 --n_time 8 --energy_res 16` for a fast smoke test (see README) | never — fully regenerates every run. Required before stages 8–9. |
| 8 | Detection sensitivity | `src/detection/detection_sensitivity.py` | stage 7 (calibration file) | `plots/phs_evaluation/sensitivity_*` | lighter than stage 7 (smaller default resolution, only the 5 test-split cases) | optional — probes below the canonical epsilon floor; nothing downstream depends on it |
| 9 | Publication figures | `src/detection/publication_figures.py` | stage 7 (its CSVs) + stage 3 (one model) | `plots/paper_figures/*` | fast (reads stage 7's CSVs, one model forward pass) | never — fully regenerates every run, but it's cheap |

Running `pytest tests/` works at any point — 31 of 32 tests need no generated data at
all, and the one that does (`test_sampler_acceptance_criteria`) skips itself gracefully
until stage 1 has run.

## Two common scenarios

**"I just cloned this and want to reproduce the paper's figures/tables"** (the common case,
since retraining isn't necessary): run stage 1, then skip straight to stages 5, 7, 9
(`python run_pipeline.py --stages sample,hallucinate,phs,figures`). Stages 2, 3, 4, 6, 8
are all either unnecessary or optional here.

**"I changed the physics/model code and want to redo everything from scratch"**: delete
the `models/*.pth` files you want retrained (the checkpoint-skip logic in stage 3 is
otherwise permanent — it will never re-train over an existing checkpoint), then
`python run_pipeline.py` end to end.
